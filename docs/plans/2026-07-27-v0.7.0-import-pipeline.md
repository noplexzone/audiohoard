# Audiohoard v0.7.0 Import Pipeline Release Plan

> **For Hermes:** Execute task-by-task with TDD, stable-diff review, and the release gates in `web-app-development-workflow` and `github-release-workflows`.

**Goal:** Stabilize current `main`, close and prove the full slskd-to-library pipeline, expose quality policy, and ship `v0.7.0`.

**Architecture:** Keep the existing FastAPI/SQLAlchemy/Alembic acquisition and import services, adding structured review decisions and a settings-backed quality profile at the existing boundaries. Prove behavior through one mocked-slskd/temp-filesystem integration flow and schema parity through a real Alembic upgrade plus metadata comparison. CI uses uniquely named required contexts so another workflow cannot satisfy the branch gate accidentally.

**Tech Stack:** Python 3.12+, FastAPI, SQLAlchemy asyncio, Alembic, Jinja2, pytest, GitHub Actions, Docker Hub.

## Global Constraints

- Branch `release/v0.7.0-import-pipeline` from current `main`.
- Do not begin Tasks 1–4 until Task 0's local full suite and PR CI are green.
- Supported quality formats: `flac`, `mp3`, `m4a/aac`, `ogg`, `opus`; shipped default order `flac → mp3`; shipped default minimum MP3 bitrate `320`; lower-quality fallback is explicit.
- `.lrc`, images, `.nfo`, and all other non-audio files are never selected as tracks.
- Complete verified albums auto-import without review. Incomplete or unverifiable releases remain in review with structured, rendered reasons.
- Manual approval must execute present tracks; execution errors and missing source paths must be visible and actionable.
- Stable release only after PR checks, merge to `main`, tag-triggered checks, Docker publication, and registry verification.

### Task 0: Repair and harden the CI gate

**Objective:** Establish why PR #21 merged, make the two reported contracts explicit, assert migration/metadata parity, and require the full suite on PRs and tags.

**Files:** `.github/workflows/ci.yml`, `.github/workflows/release.yml` if needed, `tests/integration/test_dashboard.py`, `tests/conftest.py`, and a migration/schema-parity test.

**Steps:** preserve PR #21/merge logs and protection evidence; reproduce targeted/full suites in a fresh worktree; strengthen navigation assertions to identify the active links; make fixture schema loading explicit; add a real Alembic-upgrade versus `Base.metadata` parity gate; give CI unique required contexts and `v*` coverage; update branch protection; run pytest/Ruff/mypy/build and PR CI. Do not continue until green. Commit `fix(ci): make the full release gate authoritative`.

### Task 1: Prove the slskd → staging → import lifecycle

**Objective:** Add `tests/integration/test_slskd_import_pipeline.py` with mocked slskd HTTP and a temporary filesystem for complete auto-import and incomplete review/approval. Selection must reject sidecars and low-quality duplicates, reconciliation must create real staged paths and clear the queue, complete verified releases must atomically auto-import and clean staging, and incomplete releases must state their reason and import present tracks only after approval. Commit `test(import): gate the complete slskd pipeline` plus minimal proven fixes.

### Task 2: Explain and recover review-queue blocks

**Objective:** Persist machine-readable decline reasons for incomplete manifests, failed tags, ambiguity, hash mismatch, and destination collision; render them per release with execution `error_detail`. Missing sources render exactly `source file missing: <path>` and offer per-release Dismiss/Re-acquire POST actions with CSRF/form coverage. Add the next Alembic migration if persistence requires columns. Commit `feat(imports): explain and recover blocked reviews`.

### Task 3: Expose and enforce Quality settings

**Objective:** Add a Quality settings section with reorderable supported formats, minimum MP3 bitrate 192/256/320 defaulting to 320, and explicit lower-quality fallback behavior. Conservatively bump only never-explicitly-saved legacy defaults. Keep sidecars excluded and document that choice unless lyrics-sidecar plumbing is trivial. Enforce the profile during slskd per-track candidate selection and cover the native form contract. Commit `feat(settings): expose acquisition quality policy`.

### Task 4: Review and ship v0.7.0

**Objective:** Run whole-branch spec and quality/security review, remediate blockers, write an owner-facing `v0.7.0` changelog, and update authoritative version sources. Run pytest, Ruff lint/format, mypy, package build, Docker build/smoke, final diff and secret checks. Push/open PR, require green unique CI contexts, merge, tag the exact `origin/main` commit `v0.7.0`, wait for tag CI/release, and verify `noplexzone/audiohoard:0.7.0` from Docker Hub and by manifest/pull. Do not publish `latest` unless separately authorized. Report all requested links, outputs, rendered excerpts, digest, and the owner upgrade note.
